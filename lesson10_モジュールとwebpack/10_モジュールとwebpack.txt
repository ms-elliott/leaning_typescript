通信を速くする為に、最終的にファイルを１つにくっつけることがよくあり、その為のツールを「バンドラー」と呼ぶ。
バンドラーの中でも有名なwebpackというツールとtypescriptを一緒に使う方法を学ぶ。

[135. scriptタグを並べてファイルを分割する]
    ・クラスなどでファイルを分割する
    ・index.html等のheadタグ内に各ファイルを読み込むようにscriptタグを記述する
        <script src="dist/score.js" defer></script>
    ※tsconfig.jsonで  "module":"nodeNext"になっている場合は、"module":"esnext"に変更。
    　  modeleDetection: "true"がある場合はコメントアウトする。

    -> scriptタグを読み込む(記述する)順番を間違えたりでエラーが起きやすい(古いやり方)
        最近はES6モジュールを使用してデメリットを解決できるようになった

[136. 最近はES6モジュールを使用してデメリットを解決できるようになった]
    ・他のファイルでも使用したいコンポーネント(class, interface, etc.)の先頭に「export」と記述する。
        export class Foods implements Foodsable { ... }
    ・使いたいコンポーネントをファイルの頭でimportすることで使用できる様になる。
        import { exportしたコンポーネント名 } from "ファイルパス";
        import { Foods } from "./foods";    // webpack等を使用しない場合は、ファイルパスに".js"の拡張子が必要。
    ・index.htmlのhead内でscriptタグを記述する
        <script src="dist/main.js" type="module"></script>
    ・tsconfig.json内の"compileOptions"で"module": "ES6"となっていることを確認
        import/exportはtargetではなくmodule
        ES5まではJSにファイルを分割する機能がなかった為、サードパーティによる機能が乱立。

[137. ローカルサーバを用意して、ESモジュールをブラウザで利用する]
    ・サードパーティ製のパッケージ(SERVE)を利用し、ローカルサーバを立てる
    ・SERVEをインストールする
        ターミナルで"npm install -g serve"を実行する
    ・サーバーを立てる
        ターミナルで"serve"を実行する

[138. noUncheckedSideEffectImports  ５つのimportの書き方　3つのexportの書き方]
    ・同一ファイルが複数ファイルでimportされていても、実行されるのは１度のみ
    ・「import "ファイルパス"」　と記述することで、ファイルが実行されるだけで読み込まれることはない
        この際にファイルパスが間違っていてもデフォルトではエラーを吐かないので、エラーとなるように下記を設定する
            tsconfig.json > compileOptions内に、「"noUncheckedSideEffectImports": true,」を追記
   ・importに別名を付ける
        import { Foodsable as FoodListable } from "./interface";
        import * as Interfaces from "./interface";        // 全て取得する場合は 「*」
    ・import時に{}で記述する手間を省くデフォルト設定・・・デフォルトインポート/デフォルトエクスポート　それ以外の方法は名前付きインポート/エクスポート
        export default class Foods implements Foodsable {...}   // export defaultは1つのファイルで１度しか使用できない
        import 好きな別名　from "./foods.js"

[139. type-only imports/exports varbatimModuleSyntax]
    ・型だけをimportしている場合
        import { Scoreable } from "./interfaces.js";
        import type { Scoreable } from "./interfaces.js";   // typeと記述することで型情報を参照しているだけと明示することができる
    ・型だけを参照している場合にtypeを付けないとエラーとする設定
        tsconfig.json > conpileOptions内に、「"verbatimModuleSyntax": true,」と記述する

[140. Script と　Module moduleDetection]
    ・JavaScriptには、ScriptとModuleという２種類のモードが存在する。
        ・Scriptで定義されたデータは他のファイルでも使えるが、Moduleは使えない。
        ・import/exportはModule内でのみ使用可能。
        ・HTMLのScriptタグでtype="module"と指定しているソースはmoduleとして扱われる。
    ・TypeScriptにも同様の概念があり、自動で判断している。
        ・ファイルにimport/exportがなければScript、あればModuleとして扱う。
        ・tsconfig.json > compileOptions内に、「"moduleDetection": true,」と記述すると、強制的に全てのtsファイルをモジュールとして扱うようになる。

    ・モダンでないブラウザでモジュールを使う
    ・http通信を一括で行う為(速度)
    ・コードの最適化の為

    ・HMR付きのローカルサーバーを使う為     (※ホットモジュールリプレースメント・・・何かコードに変更を加えて保存すると、ブラウザが自動的にリロードされる)

[142. webpackをインストールしてセットアップする]
    ・ターミナルで下記を実行し、package.jsonを作成する
        npm init -y
    ・webpack、webpack-cliをインストールする　  (--save-dev　開発用)
        npm install --save-dev webpack webpack-cli
    ・package.jsonを開き、"scripts"内に記述する
        "scripts" {
            "test": "echo \"Error: no test specified\" && exit ....",
            "build": "webpack"
        },
    ・上記まで設定することで、ターミナルで「npm run build」と入力すると、webpackが実行されるようになる
    ・webpack.config.jsという名前のファイルを作成し、webpack専用のconfigファイルを設定する
        const path = require('path');

        module.exports = {
            entry: './dist/main.js',
            output: {
                filename: '[contenthash]bundle.js',     // containthash・・・ファイルの内容をハッシュ値で持つ。変更があればハッシュ値に反映されキャッシュから読み込まずリロードする。
                path: path.resolve(__dirname + 'dist')         // 絶対パスで記述する
            }
        }
    ・ターミナルで「npm run build」を実行すると、コードを1行に集約したbundle.jsが生成される。
    ・htmlファイルでbundle.jsを読み込む
        <script src="dist/bundle.js" defer></script>    // defer必須

[145. ts-loaderを使用して、TypeScriptを直接webpackで扱う方法・・・moduleResolution]
    ts-loaderを使用しすると、ts->jsにコンパイル->bandle.jsを作成という順序を踏まなくても、ts->bandle.jsを作成できる
        module.exports = {
            entry: './src/food-app/main.js',
            output: {
                ・・・
            },
            devtool: 'inline-source-map',
            module: {
                rules: [{
                    test: /\.ts$/,         // 何に対してか指定する 　全てのtsファイル
                    use: 'ts-loader',
                    exclude: /node_modules/
                }]
            },
            resolve: {
                extensions: ['.ts', '.js']  // 拡張子がなかった場合に左から順に補完する
            }
        }
    ・各moduleのimport文の.jsを削除する
        import { Foods } from "./foods";
    ・＋α：　拡張子がなかった場合の拡張子の設定
        tsconfig.json > compileOptions内の "moduleResolution" : "nodeNext"      //   "Bundler"を指定すると、バンドラーと同じルールでファイルを探す

[146. webpack-dev-serverを使用して、bundleをローカルサーバから提供する]
    ・ターミナルで下記を実行する。
        npm install --save-dev webpack-dev-server
    ・package.jsonを開き、"scripts"内に記述する
        "scripts" {
            "test": "echo \"Error: no test specified\" && exit ....",
            "build": "webpack",
            "start": "webpack-dev-server",        // もしくは"webpack serve"でも同様に実行可能
        },
    ・ターミナルで「npm run start」を実行
    ・publicフォルダを作成し、その中に静的ファイル(html, css)を格納する
    ・webpack.config.js内のoutputにpublic pathを追記する
        const path = require('path');

        module.exports = {
            entry: './dist/main.js',
            output: {
                filename: '[contenthash]bundle.js',
                path: path.resolve(__dirname + 'dist'),
                publicPath: '/dist/'
            }
        }
    ・ソースを変更した上で保存すると、ブラウザに自動的に変更が反映される　(ホットモジュールリプレイスメント)

[147. 本番用の設定でwebpackを使う]
        const path = require('path');

        module.exports = {
            mode: 'production',   // production:本番 or development:開発
            entry: './dist/main.js',
            output: {
                filename: '[contenthash]bundle.js',
                path: path.resolve(__dirname + 'dist'),
                publicPath: '/dist/'
            }
        }
    ・上のやり方だといちいちmodeの設定を書き換えないといけない為、面倒。
    　->設定ファイルを本番・開発用に２つ作成して切り替えることが可能
        ①webpack.prod.js
        ②webpack.dev.js
            ・package.jsonを書き換える
                "scripts" {
                    "test": "echo \"Error: no test specified\" && exit ....",
                    "build": "webpack --config webpack.prod.js",
                    "start": "webpack --config webpack.dev.js",
                },

    ・本番用でよく使われる設定
        ・CleanWebpackPlugin
            ・・・Webpackによるビルド（コンパイル）処理の前に、出力先フォルダ（通常はdistなど）の中身をきれいに削除（クリーン）してくれるWebpackプラグインです。
            ・ターミナルでインストールする
                npm install --save-dev clean-webpack-plugin
            ・設定ファイル内に記述する
                const path = require('path');
                const { CleanWebpackPlugin } = require('clean-webpack-plugin');

                module.exports = {
                    mode: 'production',
                    ・・・
                },
                ・・・
                plugins: [
                    new CleanWebpackPlugin()
                ]
